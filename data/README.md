# Data Directory

## Wrist motor telemetry

New 9DoF LeRobot collections can optionally save wrist motor diagnostics in addition to the existing training state and action.

The optional Parquet columns are:

- `telemetry.wrist_motor_position_raw`: actual motor positions, ordered as `j1_present_raw`, `j2_present_raw`.
- `telemetry.wrist_motor_goal_raw`: motor targets generated by the OpenRB controller, ordered as `j1_goal_raw`, `j2_goal_raw`.
- `telemetry.wrist_motor_rate_raw_s`: motor rates, ordered as `j1_rate_raw_s`, `j2_rate_raw_s`.

These columns are diagnostics only. They do not change the existing 9D training contract:

- `observation.state[6:8]`: actual wrist FE/RU positions measured by the endpoint encoders, in radians.
- `action[6:8]`: commanded wrist FE/RU target positions, in radians.

PI0.5 training ignores the motor telemetry unless a future training schema explicitly selects it.

### Enable or disable future collection

The setting is in `configs/input_schemas/ur5e_wrist_gripper_9dof.yaml`:

```yaml
telemetry:
  wrist_motor:
    enabled: true
```

Set `enabled: false` to omit these columns from future collections. Changing this setting does not modify datasets that have already been recorded.

### Removing telemetry from an existing dataset

Keeping the columns is normally preferable because training ignores them and they remain useful for diagnosing motor-to-endpoint tracking.

If physical removal is required, create a converted dataset copy and remove all three telemetry columns from every Parquet file. The corresponding entries and statistics must also be removed from:

- `meta/info.json`
- `meta/stats.json`
- `meta/robot_teleoperation_contract.json`

Do not remove only the Parquet columns or only the metadata. That produces an inconsistent LeRobot dataset and can break validation or dataset merging. Preserve the original dataset until the converted copy passes validation.

## Automatic 2DoF/3DoF aggregation

After a finalized TASK2 9DoF collection, every Episode is classified independently from its recorded wrist target actions. A single timestamped session can therefore update both aggregate directories:

- `lerobot/real-9D/2DoF-only`: Episodes where at least one FE/RU target action range reaches the configured threshold.
- `lerobot/real-9D/3DoF-only`: Episodes where both FE/RU target action ranges remain below the threshold.

The score uses peak-to-peak target movement:

```text
max(FE action) - min(FE action)
max(RU action) - min(RU action)
```

The threshold is configured in `configs/dataset.yaml` as `wrist_auto_merge.action_range_threshold_deg`. Its default is 5 degrees. Existing data has a clear separation: inactive wrist actions are 0 degrees, while the smallest active wrist episode has about 13.14 degrees of target movement.

Classification uses `action`, not endpoint encoder observations, so encoder drift and mechanical backlash do not count as intentional wrist movement. The original timestamped session remains complete and unchanged. LeRobot's Episode split tooling reindexes data rows, episode metadata, statistics, and all three videos before each non-empty group is merged. Each aggregate replacement is staged and atomic; the original session remains available for recovery if any group update fails.
